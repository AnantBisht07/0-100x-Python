Part 02

The mental model

Get these four ideas straight before installing anything. They remove most of the confusion beginners run into.

Python is two things with the same name

The language is the rules for writing instructions. The interpreter is the actual program on your computer that reads your .py file and runs it. When people say "install Python," they mean install the interpreter.

A package manager installs code other people wrote

Almost no real program is written from scratch. You pull in existing libraries. The package manager fetches them, installs the correct versions, and tracks what your project needs. Ours is uv.

A virtual environment is a clean, isolated box for one project

Different projects need different library versions. Without isolation, installing something for project A can break project B. A virtual environment gives each project its own private set of libraries so they never collide. uv creates and manages this box for you automatically. You will never manage it by hand.

The four tools

uv

Installs Python, manages your project, installs libraries, and runs your code.

ruff

Formats your code and flags mistakes, instantly.

VS Code

The editor where you write code.

git / GitHub

Saves your work's history and publishes it online.

That is the whole workshop. uv is the centerpiece.

Part 03

Why uv, and why not pip?

This is the question that decides whether you are learning the 2026 standard or the 2019 one. Here is the honest reasoning.

The old way

For years, a Python beginner had to learn several separate tools that each did one part of the job:

Tool (old stack)What it did
pipInstalled libraries
venv / virtualenvCreated the isolated box
pyenvManaged which Python version you used
poetry / pip-toolsLocked exact versions for reproducibility

You had to install them, learn them, and wire them together correctly. The classic beginner experience was losing days to "it works on my machine but not yours," activating and deactivating environments by hand, and fighting version conflicts.

What uv changes

uv replaces all four of those tools with one fast program. One command initializes a project, installs the right Python, creates the isolated environment, installs libraries, and locks exact versions so the project runs identically on any machine.

ConcernOld wayuv
Tools to learn3-4 separate tools1
SpeedSlow installs10-100x faster (built in Rust)
Reproducible across machinesManual, error-proneAutomatic, via a lockfile
Manage Python versionsA separate tool (pyenv)Built in
Activate the environmentBy hand, easy to forgetuv handles it (uv run)

So why not just use pip?

You can still use pip. It is not broken. But for someone learning in 2026, starting with uv means fewer moving parts, no "forgot to activate the environment" bugs, and projects that are reproducible by default, which is exactly the professional habit employers expect.

The honest counterpoint

Most tutorials, Stack Overflow answers, and older courses still say pip install X. You will see pip everywhere, and that is fine. The translation is almost always one-to-one.

You see onlineYou type
pip install requestsuv add requests
python script.pyuv run script.py
python -m venv then activatenothing, uv does it

The same logic for ruff

The old stack used three tools: black (formats code), flake8 (finds mistakes), and isort (orders imports). ruff does all three, in one tool, in milliseconds. Same pattern: fewer tools, faster, one config file. It is used by major projects like FastAPI and Hugging Face, so it is not a toy choice.

Bottom line

We teach uv and ruff because they are simpler and the current professional standard. You get the easier path and the resume-relevant path at the same time. That is rare. Take it.

Part 04 · Hands-on

The install lab

Do these in order. After each step there is a success check. Do not move on until it passes.

1

Install uv

uv installs with a single command. The official page is the source of truth: docs.astral.sh/uv. The commands below are the standard ones.

terminal · macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
powershell · Windows
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Close and reopen the terminal after installing.

✓

Success checkRun uv --version. You should see a version number. If you see "command not found," check Troubleshooting.

2

Install Python (via uv)

You do not download Python from a website. uv does it:

terminal
uv python install 3.14
✓

Success checkRun uv python list. You should see a 3.14 entry.

3

Install VS Code + extensions

  1. Install VS Code from code.visualstudio.com.
  2. Open it and go to the Extensions panel (the squares icon on the left).
  3. Install the Python extension (by Microsoft) and the Ruff extension (by Astral).
✓

Success checkThe Extensions panel shows both Python and Ruff as installed.

4

Install git + create a GitHub account

  1. Install git from git-scm.com (it may already be installed).
  2. Create a free account at github.com.
✓

Success checkRun git --version. You should see a version number, and you can log in to github.com.

5

Create your first project

Create the project pinned to Python 3.14, then enter it:

terminal
uv init python-core --python 3.14
cd python-core

Open the folder in VS Code with code . and look at what uv created:

FileWhat it is
main.pyA starter program
pyproject.tomlYour project's config and dependency list
.python-versionPins this project to Python 3.14
README.mdProject description (auto-created)
.gitignoreTells git what to ignore

Now run it:

terminal
uv run main.py
✓

Success checkYou see Hello from python-core! printed. On this first run, uv quietly creates a .venv/ folder and a uv.lock file: the isolated box and the version lock, made for you. You never typed a single environment command.

Part 05 · The win

Your first program

The starter file just prints a fixed line. Let's make Python actually do something with input and math. This is a preview of Week 1.

Open main.py in VS Code, delete what's there, and type this exactly:

main.py
name = input("What's your name? ")
print(f"Hello, {name}! You just ran a program you wrote.")

birth_year = int(input("What year were you born? "))
age = 2026 - birth_year
print(f"You are about {age} years old.")

Run it:

terminal
uv run main.py

It asks your name, asks your birth year, and prints a personalized result. You just used three things you will formally learn in Week 1: input, f-strings, and converting text to numbers for math.

Now format and check it with ruff

Format the code (auto-fixes spacing and style):

terminal
uvx ruff format .

Check it for mistakes:

terminal
uvx ruff check .
Note

uvx runs a tool without installing it into your project. In Week 1 you will add ruff to the project properly. For today, this is enough to see it work.

The loop you'll repeat for 12 weeks

write → run → format → check

Troubleshooting

Most first-session problems are one of these. Find your symptom, apply the fix.

SymptomCauseFix
uv: command not foundTerminal hasn't picked up uv's locationFully close and reopen the terminal, or restart it.
uv run says no Python foundVersion not installedRun uv python install 3.14 again.
Commands run but nothing happensYou're in the wrong foldercd python-core first. Confirm main.py is there with ls (or dir on Windows).
Ruff does nothing in VS CodeExtension not active for this folderReopen the folder via code . from inside the project.
input() errors outTyped non-numeric text for birth yearRe-run and enter a number like 2001.
Permission error on Windows installPowerShell policyUse the exact PowerShell command given; it sets the policy for that one command only.
