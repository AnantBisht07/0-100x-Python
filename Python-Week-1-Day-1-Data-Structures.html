Part 01

The big picture

A single value, like age = 25, holds one thing. Real programs deal with many things at once: a list of prices, a customer's details, a collection of tags. Data structures are the containers that hold many values in an organized way.

Python gives you four built-in containers. Almost everything you build uses one or more of them. The entire skill is knowing which container fits the job, and this one table is the answer. Everything else in this handbook is detail underneath it.

StructureOrdered?Changeable?Looked up byDuplicates?Written with
ListYesYesPosition [0]Allowed[ ]
TupleYesNoPosition [0]Allowed( )
DictYesYesKey ["name"]Keys must be unique{key: value}
SetNoYesNot indexedRemoved automatically{ }

Two questions sort out almost every choice:

  • Do I find items by position or by a label? Position means list or tuple. A label means dict.
  • Will this data change after I create it? If it must stay fixed, use a tuple.
One accuracy note

Older tutorials call dictionaries "unordered." Since Python 3.7 that is no longer true: dictionaries remember the order you inserted items. You can trust the order now.

Part 02

Lists

A list is an ordered collection you can change. It is the structure you'll use most.

A numbered shopping list. Items sit in order, and you can add, cross off, or rewrite any line.

Creating a list

main.py
scores = [85, 92, 78]     # a list of numbers
names = ["Alice", "Bob"]      # a list of strings
mixed = [1, "two", True]      # types can be mixed
empty = []                    # an empty list, to fill later

Reading items by position (indexing)

Lists are zero-indexed: the first item is at position 0. Negative numbers count from the end.

main.py
scores = [85, 92, 78]
print(scores[0])    # 85  (first item)
print(scores[-1])   # 78  (last item)
print(scores[0:2])  # [85, 92]  (a slice: positions 0 and 1)

Changing a list

This is what "mutable" means: you can edit it after it exists.

main.py
scores = [85, 92, 78]
scores[0] = 90        # change a value      -> [90, 92, 78]
scores.append(100)    # add to the end      -> [90, 92, 78, 100]
scores.remove(92)     # remove a value      -> [90, 78, 100]
last = scores.pop()    # remove + return last -> last = 100

The methods you'll actually use

MethodWhat it does
append(x)Add x to the end
insert(i, x)Insert x at position i
remove(x)Remove the first x
pop()Remove and return the last item
sort()Sort the list in place
reverse()Reverse the order in place
len(list)How many items (a built-in, not a method)
x in listIs x present? Gives True/False

Looping over a list

main.py
for score in scores:
    print(score)
Use a list when you have an ordered collection of items you'll add to, remove from, or change, and you find them by position.

Part 03 · The leap

Dictionaries

A dictionary stores data as key: value pairs. Instead of finding things by position, you find them by a meaningful label. This is the most important idea of the week.

A phone book. You don't read it front to back; you jump straight to a name and read the number beside it.

That analogy also explains why dictionaries matter: looking up a value by its key is extremely fast, even among millions of entries, because you go straight to it instead of scanning.

Creating and reading a dictionary

main.py
person = {
    "name": "Alice",
    "age": 25,
    "city": "Delhi",
}

print(person["name"])   # Alice  (look up by key)
print(person["age"])    # 25

The KeyError trap, and how to avoid it

Asking for a key that doesn't exist crashes the program with a KeyError. The safe way to read a maybe-missing key is .get(), which returns None (or a default you choose) instead of crashing.

main.py
print(person["email"])              # crashes: KeyError
print(person.get("email"))          # None  (safe)
print(person.get("email", "N/A"))   # N/A  (safe, with a default)

Adding, updating, and removing

main.py
person["email"] = "alice@mail.com"   # add a new pair
person["age"] = 26                  # update an existing key
del person["city"]                  # remove a pair

The methods you'll actually use

MethodWhat it does
get(key, default)Read a key safely, no crash if missing
keys()All the keys
values()All the values
items()All key-value pairs, for looping
update(other)Merge another dict in
key in dictDoes this key exist?

Looping over a dictionary

Use .items() to walk through both the key and the value together.

main.py
for key, value in person.items():
    print(f"{key}: {value}")

name: Alice
age: 26
email: alice@mail.com

The rules for keys

Keys must be unique (a second use of the same key overwrites the first) and unchangeable types like strings or numbers. Values can be anything, including lists or other dictionaries.

Use a dict when each piece of data has a natural label or identity, and you want to look it up by that label rather than by position.

Part 04

Tuples

A tuple is just a list that can never change. Same ordering, same indexing, but locked after creation.

GPS coordinates. A point like (28.6, 77.2) is one fixed thing; editing half of it would be meaningless.

Creating and reading

main.py
point = (28, 77)
print(point[0])     # 28  (index just like a list)

point[0] = 30       # crashes: tuples cannot be changed

Unpacking: a tuple's best trick

You can split a tuple straight into separate variables in one line. This is everywhere in real Python.

main.py
point = (28, 77)
x, y = point        # x = 28, y = 77
print(x, y)

Why tuples exist

  • Safety. Data that should never change (a date of birth, a coordinate, fixed settings) can't be edited by accident.
  • They can be dictionary keys. Because they never change, tuples are allowed as keys; lists are not.
  • Returning several values. A function that returns (min, max) is returning a tuple.
Use a tuple when a group of values belongs together and must stay fixed for the life of the program.

Part 05

Sets

A set is an unordered collection of unique items. Duplicates are removed automatically, and there is no position or index.

A guest list with no repeats. Add the same name twice and it still appears once.

Creating a set, and the duplicate magic

main.py
colors = {"red", "green", "red"}
print(colors)        # {'red', 'green'}  (the duplicate is gone)

empty = set()        # NOTE: {} makes an empty DICT, not a set

The one job sets are great at: removing duplicates

main.py
numbers = [1, 2, 2, 3, 3, 3]
unique = set(numbers)       # {1, 2, 3}
print(len(unique))         # 3  (how many distinct values)

Core operations

OperationWhat it does
add(x)Add an item
discard(x)Remove an item if present (no crash if absent)
x in setFast membership test
a | bUnion: everything in either set
a & bIntersection: items in both sets
a - bDifference: items in a but not b
Use a set when you only care whether items are present and unique, and you don't need order or position.

Part 06 · Modern Python

Comprehensions

A comprehension builds a new collection from an existing one in a single readable line. This is the standard, professional way to do it in 2026, so learn it now, not "later."

The long way vs the comprehension

main.py
# goal: double every number

# the long way
doubled = []
for n in [1, 2, 3]:
    doubled.append(n * 2)

# the comprehension (same result)
doubled = [n * 2 for n in [1, 2, 3]]   # [2, 4, 6]

Add a condition to filter

main.py
nums = [3, 12, 5, 20, 8]
big = [n for n in nums if n > 10]   # [12, 20]

Dict and set comprehensions too

main.py
squares = {n: n * n for n in [1, 2, 3]}   # {1: 1, 2: 4, 3: 9}
unique  = {n for n in [1, 1, 2]}        # {1, 2}
Key idea

Read a comprehension right to left: "for each n in the data, (optionally if it passes a test), put this expression into the new collection." It is a loop, compressed into the shape of the result.

Part 07

Choosing the right one

A short decision guide, then the traps that catch every beginner.

The decision guide

If you need to...Reach for
Keep an ordered collection you'll changeList
Look data up by a label or nameDict
Lock a group of values so they can't changeTuple
Track unique items or remove duplicatesSet

Traps to avoid

The trapThe fix
Using a list when you keep searching it for a labelThat's a dict's job. Switch to key lookup.
dict[key] crashing on missing keysUse dict.get(key, default).
Expecting a set to keep order or duplicatesIt won't, by design. Use a list if you need those.
Writing {} for an empty set{} is an empty dict. Use set().
Trying to change a tupleYou can't. Use a list if the data must change.

Part 08 · Solved together

Worked examples

We solve these two in class. One drills lists, one drills dictionaries, the two structures you'll lean on most.

Example 1 · Lists

A simple gradebook

Collect scores, add a new one, then report the total, average, and highest. This uses list methods plus the built-ins sum, len, and max.

main.py
scores = [85, 92, 78, 90, 88]
scores.append(95)              # a new score arrives

total = sum(scores)
average = total / len(scores)
highest = max(scores)

print(f"All scores: {scores}")
print(f"Average:    {average}")
print(f"Highest:    {highest}")

All scores: [85, 92, 78, 90, 88, 95]
Average: 88.0
Highest: 95

sum, len, and max are built-in functions that work on any list. You did the same kind of total and max by hand with loops on Day-2 of loops; here they come for free.

Example 2 · Dictionaries

A contact record

Store one person's details, read a field safely, add a new field, then print every field with a loop. This is the exact shape behind tomorrow's project.

main.py
contact = {
    "name": "Alice",
    "phone": "555-0100",
    "city": "Delhi",
}

print(contact["name"])                 # direct lookup
print(contact.get("email", "no email"))  # safe lookup of a missing key

contact["email"] = "alice@mail.com"     # add a field

for field, value in contact.items():
    print(f"{field}: {value}")

Alice
no email
name: Alice
phone: 555-0100
city: Delhi
email: alice@mail.com

Notice the pattern: a dict holds one labeled record, and .items() walks every label and value. Put many of these dicts in a list, and you can model an entire address book, which is exactly where Day 2 goes.

Where this is heading

A list of dictionaries is the most useful shape in real programming: a list of records, each record a labeled dict. Today you learned both halves. Tomorrow you combine them into a real project.
