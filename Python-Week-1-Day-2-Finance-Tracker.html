Part 01

The shape that models everything

One record is a dict. Many records is a list of dicts. That single sentence describes the data inside almost every real application.

Look at what this shape can represent:

AppThe list holds...Each dict holds...
Contacts appAll contactsname, phone, email
Online storeAll productsname, price, stock
Expense trackerAll expensesname, amount, category
PlaylistAll songstitle, artist, duration

The division of labor is exact. The dict gives each record labeled fields. The list gives you an ordered, growable collection of those records. Here is one expense record, then a collection of them:

main.py
# one record: a dict
expense = {"name": "Coffee", "amount": 150, "category": "food"}

# many records: a list of dicts
expenses = [
    {"name": "Coffee",  "amount": 150,  "category": "food"},
    {"name": "Bus pass", "amount": 500,  "category": "travel"},
    {"name": "Movie",   "amount": 300,  "category": "fun"},
]
Key idea

Dict = one labeled record. List = the growing collection. Master this combination and you can model the data of nearly any application.

Part 02

Working the shape: the four moves

Everything you do with a list of dicts reduces to four moves. Learn these and the project is straightforward.

Move 1 · Add a record

main.py
new = {"name": "Book", "amount": 450, "category": "study"}
expenses.append(new)

Move 2 · Loop and read fields

Each pass, the loop variable is one whole dict. Read its fields by key.

main.py
for e in expenses:
    print(f"{e['name']}: {e['amount']} ({e['category']})")

Coffee: 150 (food) Bus pass: 500 (travel) Movie: 300 (fun)

Move 3 · Total a field (accumulator, or comprehension)

main.py
# the loop way (Week 0 pattern)
total = 0
for e in expenses:
    total += e["amount"]

# the comprehension way (yesterday's tool)
total = sum(e["amount"] for e in expenses)   # 950

Move 4 · Filter by a field

main.py
food = [e for e in expenses if e["category"] == "food"]
Quote marks inside quote marks

Inside an f-string written with double quotes, use single quotes for keys: f"{e['name']}". Mixing them wrong is the most common syntax error today.

Part 03 · Solved together

Worked example

Example · All four moves at once

A mini product catalog

A shop's inventory: add a product, list everything, total the stock value, and filter the cheap items. This is the exact skeleton of the tracker, on different data.

main.py
products = [
    {"name": "Pen",      "price": 20,  "stock": 100},
    {"name": "Notebook", "price": 60,  "stock": 40},
]

# Move 1: add a record
products.append({"name": "Bag", "price": 900, "stock": 5})

# Move 2: loop and print
for p in products:
    print(f"{p['name']}: ₹{p['price']} ({p['stock']} in stock)")

# Move 3: total value of all stock (price × stock, summed)
value = sum(p["price"] * p["stock"] for p in products)
print(f"Total stock value: ₹{value}")

# Move 4: filter items under ₹100
cheap = [p["name"] for p in products if p["price"] < 100]
print(f"Under ₹100: {cheap}")

Pen: ₹20 (100 in stock) Notebook: ₹60 (40 in stock) Bag: ₹900 (5 in stock) Total stock value: ₹8900 Under ₹100: ['Pen', 'Notebook']

Note Move 3: the comprehension can compute per record (price * stock) before summing. One line replaces a whole accumulator loop.

Part 04 · The build

Finance Tracker v1

A menu-driven expense tracker. It runs until you quit, and supports: add an expense, list all, show the total, filter by category. Build it step by step; run after every step.

1

The skeleton: a menu that loops

Start with the app's frame: an empty list, and a while True loop showing a menu. Option 5 uses break to quit. Everything else plugs into this frame.

main.py
expenses = []

while True:
    print("\n=== Finance Tracker ===")
    print("1. Add expense")
    print("2. List all")
    print("3. Total spend")
    print("4. Filter by category")
    print("5. Quit")

    choice = input("Choose (1-5): ")

    if choice == "5":
        print("Goodbye!")
        break

Run it. You should see the menu repeat until you enter 5.

2

Option 1: add an expense

Ask for the three fields, build a dict, append it. This is Move 1 plus Week 0's input and type conversion. Add this inside the loop:

main.py (inside the while loop)
    elif choice == "1":
        name = input("Expense name: ")
        amount = float(input("Amount: "))
        category = input("Category: ").lower()
        expenses.append({"name": name, "amount": amount, "category": category})
        print(f"Added: {name}")
Why .lower()

Storing categories lowercased means "Food" and "food" count as the same category when you filter later. Normalize data when it enters, not when you read it.

3

Option 2: list all expenses

Move 2, with one addition: enumerate numbers each row for a readable display. Handle the empty case explicitly.

main.py (inside the while loop)
    elif choice == "2":
        if not expenses:
            print("No expenses yet.")
        else:
            for i, e in enumerate(expenses, start=1):
                print(f"{i}. {e['name']} — ₹{e['amount']} ({e['category']})")
Two things here

if not expenses: is truthiness from Week 0: an empty list counts as False. enumerate(..., start=1) gives you a counter and the item together, starting at 1 for humans.

4

Option 3: total spend

Move 3 in one line.

main.py (inside the while loop)
    elif choice == "3":
        total = sum(e["amount"] for e in expenses)
        print(f"Total spend: ₹{total}")
5

Option 4: filter by category

Move 4: ask which category, filter with a comprehension, print the matches and their subtotal.

main.py (inside the while loop)
    elif choice == "4":
        cat = input("Which category? ").lower()
        matches = [e for e in expenses if e["category"] == cat]
        if not matches:
            print(f"Nothing in '{cat}'.")
        else:
            for e in matches:
                print(f"- {e['name']}: ₹{e['amount']}")
            subtotal = sum(e["amount"] for e in matches)
            print(f"Subtotal: ₹{subtotal}")

    else:
        print("Invalid choice, try 1-5.")

The final else catches any input that isn't 1-5. Run the full app: add a few expenses across categories, list them, total them, filter them, quit. If all five options behave, v1 is shipped.

Known limits of v1 (on purpose)

Typing letters where a number is expected crashes the app, and all data vanishes when you quit. Both are real flaws, and both are the exact topics of upcoming weeks (error handling, then file storage). Noticing the flaws now is the point.

What you shipped

A running application: a persistent loop, a menu, user input, and a list-of-dicts data model with add, list, total, and filter. Every future version of this app builds on today's file.

Homework: extend the tracker

Six extensions, easiest first. Each adds one feature to your own tracker. You are modifying a real codebase now, which is exactly what programming is.

Extensions

  2. In the list view, show amounts with 2 decimal places.f-string formatting: {value:.2f}
  3. Add option 6: show the most expensive expense.Loop with a "biggest so far" variable (Week 0 warm-up), comparing e["amount"].
  4. Add option 7: show the average expense amount.Total divided by count. Guard the empty-list case: dividing by zero crashes.
  5. Add option 8: list all unique categories.A set comprehension over e["category"] does it in one line.
  6. Add option 9: spend per category, every category with its subtotal. capstoneBuild a dict: category as key, running subtotal as value. Loop expenses, add each amount to its category's entry.
